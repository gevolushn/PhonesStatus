# PhonesStatus

Порівнює статуси внутрішніх телефонів між таблицею і поточним станом АТС:
показує, які номери підключились, а які відключились.

Дані беруться з двох джерел, і **кожне має власний перемикач Ручний / Авто** —
незалежний від іншого. Тобто можна тягнути статуси з АТС автоматично, а таблицю
вказувати руками, або навпаки.

| Джерело | Ручний режим | Авто-режим |
|---|---|---|
| **FreePBX** | вставка списків Online / Offline | Asterisk REST Interface (один запит) |
| **Таблиця** | локальний файл `.xlsx` | Google Sheets (API-ключ) |

---

## Як користуватись

1. **Панель «Таблиця»** — режим **Ручний**: вкажіть файл `.xlsx` кнопкою «Огляд…».
   Під полем видно, який аркуш і які колонки будуть використані.
   Режим **Авто** — посилання на Google-таблицю й API-ключ у **⚙ Налаштування**
   (див. розділ нижче).
2. **Панель «FreePBX»**:
   - режим **Ручний** — скопіюйте з FreePBX список Online у верхнє поле, Offline у нижнє.
     Формат довільний: підходить і `PJSIP  1001  0`, і голий стовпчик номерів;
   - режим **Авто** — заповніть адресу ARI, логін і пароль у **⚙ Налаштування**.
3. Натисніть **«▶ Порівняти»**.
4. Результат — кольоровий звіт; **«💾 Зберегти TXT»** вивантажує його у файл.

Шлях до таблиці, режими джерел, розкладка колонок, розмір/позиція вікна й тема
зберігаються між запусками (`data/settings.json`).

### Що саме порівнюється

- **Зміни** — лише номери, присутні **в обох** джерелах, у яких статус **відрізняється**.
- Додатково звіт показує номери **поза перетином**:
  - «в АТС, немає в таблиці» — показується завжди;
  - «у таблиці, немає в АТС» — **лише в авто-режимі АТС**. У ручному режимі цей список
    дорівнював би «все, чого ви не вставили», тому там він приховується.
- З таблиці беруться колонки, вказані в налаштуваннях (за замовчуванням **F** — номер,
  **H** — статус `ON`/`OFF`). Аркуш — заданий явно або визначений автоматично за словом
  «телефон» у назві (аркуші зі словами `старий`, `copy of`, `експорт` ігноруються).
- Приймаються числа з **3–5 цифр**. Комірка має бути **чистим числом**: `901 (Binotel)`
  не розпізнається — це номер зовнішньої АТС, свідомо поза порівнянням.
- Зі вставленого тексту береться перший токен рядка, що **цілком** складається з 3–5 цифр.
  Номер усередині більшого токена (`SIP/1005-00001`) **не** розпізнається.
- Якщо номер вклеїли і в Online, і в Offline — перемагає **Offline**.

## Авто-режим FreePBX (Asterisk ARI)

Статуси беруться одним запитом `GET /endpoints` до Asterisk REST Interface.
GraphQL/REST **самого FreePBX не підходить** — він віддає лише статичну конфігурацію
extension'а, а стан реєстрації живе в Asterisk.

Разове налаштування на боці АТС:

1. `Settings → Asterisk REST Interface Users` — створити користувача, **Read Only: Yes**.
2. Увімкнути Asterisk Builtin mini-HTTP Server, `Bind Address 0.0.0.0`, порт `8088`
   (якщо програма працює не на самому сервері АТС).
3. У програмі: **⚙ Налаштування → FreePBX / Asterisk** — адреса (`http://<сервер>:8088/ari`),
   логін, пароль.

Пароль зберігається зашифрованим через **Windows DPAPI** — ключ прив'язаний до вашого
облікового запису Windows, тож скопійований на інший ПК `settings.json` не розшифрується.
Захист від копіювання файлу, **не** від коду, виконаного під вашим же обліковим записом.

## Авто-режим таблиці (Google Sheets)

Читання йде через **Google Sheets API v4 з API-ключем**. Ключ потрібен не для
доступу до таблиці (вона й так відкрита за посиланням), а щоб запити рахувались
по **вашій квоті** в Google Cloud, а не як анонімний трафік: анонімне завантаження
Google має право зустріти сторінкою «unusual traffic», кодом 429 або капчею.

Разове налаштування:

1. Таблиця має бути відкрита як **«Будь-хто, хто має посилання — Переглядач»**.
2. В [Google Cloud Console](https://console.cloud.google.com/) створити проєкт,
   увімкнути **Google Sheets API** і створити **API key** (безкоштовно).
   Раджу одразу обмежити ключ: *API restrictions* — лише Google Sheets API.
3. У програмі: **⚙ Налаштування — Google Sheets** — вставити посилання (просто
   скопійоване з адресного рядка) і ключ.

Аркуш і колонки беруться з розділу **«Розкладка таблиці»** — ті самі, що для `.xlsx`.

Ключ зберігається зашифрованим через DPAPI, як і пароль ARI.

> ⚠️ Якщо Google відповість `HTTP 400`, дивіться текст помилки: той самий код
> повертається **і на протухлий ключ, і на неправильну назву аркуша**. Програма
> їх розрізняє й пише, що саме сталося.

## Запуск для розробки

```bash
pip install -r requirements.txt
python main.py
```

Залежностей лише дві: `customtkinter` і `openpyxl`. ARI працює на `urllib`,
шифрування — на `ctypes` (обидва зі стандартної бібліотеки).

## Перша збірка: updater.exe (один раз)

Шаблон постачає `assets/updater/updater_src.py`, але **не** зібраний `updater.exe`.
Перед першою portable-збіркою зберіть його один раз:

```bash
cd assets/updater
pyinstaller --onefile --noconsole --name updater updater_src.py
copy dist\updater.exe updater.exe
rmdir /s /q dist build __pycache__
del updater.spec
```

Після цього `updater.exe` версіонується у репозиторії. Перезбирати лише при зміні
`updater_src.py`.

## Збірка .exe

```bash
pyinstaller build_portable.spec
# Результат: dist/PhonesStatus_1.2.1_portable.exe   (ім'я = APP_NAME_APP_VERSION)
```

> Spec сам пише тип дистрибуції у `core/_build_dist.py` і бере назву/версію з
> `core/build_info.py`. Версію змінювати лише в `build_info.py` (`APP_VERSION`).

## Оновлення

Автоперевірка через GitHub Releases передбачена ядром, але **вимкнена**
(`update_check: "never"` у `data/settings.json`) — релізів ще немає.

Щоб увімкнути: викласти реліз із asset `PhonesStatus_X.Y.Z_portable.exe`, створити
`core/_build_secrets.py` з `GITHUB_TOKEN` (fine-grained PAT, лише `Contents: Read-only`)
і вибрати частоту у **⚙ Налаштування → Оновлення** (`startup` / `daily` / `weekly`).

> ⚠️ Токен **не** кладеться в `core/build_info.py` — той файл версіонується, і токен
> назавжди осів би в git-історії. Шаблон файлу секретів — `core/_build_secrets.py.example`;
> сам `_build_secrets.py` у `.gitignore`.

## Теми

Чотири режими оформлення (вибір зберігається у `data/settings.json`):
- **☀ Світла** — білий фон
- **🌥 Сіра** — темно-сірий (Word-style)
- **🌙 Темна** — майже чорний (за замовчуванням)
- **⚙ Система** — з налаштувань Windows

## Структура

```
core/       ядро шаблону: логер, конфіг, шляхи, оновлення, події, DPAPI
gui/        вікна й віджети: головне вікно, налаштування, теми, фонові задачі
parsers/    джерела даних + порівняння; table_rules — спільні правила читання
            таблиці для .xlsx і Google Sheets (щоб вони не розійшлись)
formatters/ формування звіту
```

Усі джерела даних повертають **однакову структуру** — словник «номер → ON/OFF».
Саме тому порівняння й звіт не знають, з якого режиму прийшли дані.

## Конфігурація проєкту

Уся ідентичність — у `core/build_info.py` (`APP_NAME`, `APP_VERSION`, `GITHUB_REPO`,
`GITHUB_PRIVATE`, `TEMP_PREFIX`, `TEMPLATE_VERSION`). Решта значень обчислюється з них.

Побудовано на Python Desktop App Template `2.5.0`. Опційні модулі шаблону —
у `optional_modules/`, див. `optional_modules/README_OPTIONAL_MODULES.md`.
